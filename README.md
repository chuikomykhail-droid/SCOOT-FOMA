# Scoot Foma

Симулятор трюкового самоката на Unity, где игрок с геймпада управляет **частями тела райдера**, а трюки получаются **из физики**, а не из анимаций.

Левый стик — руки и руль, правый — корпус, курки и бамперы — ноги и хват. Тейлвип случается потому, что нога пнула деку, а не потому что нажата кнопка «тейлвип». Главная ценность проекта — продуманное управление.

## Идея

В существующих играх про самокат трюки запускаются комбинациями кнопок или анимациями. Полностью физическое управление частями тела есть только у скейта (Skater XL). Здесь:

- один орган управления — одна часть тела; состояние (езда, воздух, слайд) меняет ответ физики, а не смысл кнопки;
- трюки возникают сами, комбо (вип + барспин, 360 + вип) работают, если работают части;
- только внутренние силы: в воздухе нельзя «докрутить» стиком, вращение набирается при отрыве;
- ассист отдельным слоем, с ползунками, без анимаций.

## Технологии

Unity 6 (6000.6), новый Input System, физика PhysX на **240 Гц**. Райдер и самокат — две отдельные `ArticulationBody` (13 и 4 звена), мышцы — приводы суставов. Хват руки — через лёгкую кисть-посредник на `Joint`, стопы стоят на деке контактом с мягким ограниченным прилипанием.

## Архитектура

Слои работают кадрами-структурами и не знают друг о друге:
**ввод → намерения → ассист → физика → сенсоры/распознавание.** Распознавание ничего не двигает. Шаг физики ведёт один оркестратор (`SimulationLoop`), визуал интерполируется отдельно.

```
Assets/_Project/
  Scripts/Core/      чистая логика без Unity-объектов: фильтры ввода, флик, защёлка, намерения, IK, момент импульса
  Scripts/Runtime/   MonoBehaviour-обёртки: геймпад, оркестратор, сборка самоката и райдера, отладочный HUD
  Scripts/Editor/    сборщики сцен (меню Scoot Foma)
  Tests/             EditMode-тесты ядра
  Settings/          коэффициенты в ассетах, а не в коде
```

Подробности и результаты технических проверок физики — в [docs/spikes.md](docs/spikes.md).

## Запуск

1. Открыть проект в Unity 6000.6.
2. Меню **Scoot Foma → Build Input Lab** и открыть сцену `Assets/_Project/Scenes/InputLab.unity`. На экране видно, что делают стики и куда уходят цели частей тела. **F5** — запись ввода, **F1** — скрыть HUD.
3. Спайки физики: **Scoot Foma → Spikes → Build All Spike Scenes**.
4. Тесты: Window → General → Test Runner → EditMode.

## Планы

Когда управление и физика будут готовы, на этой системе планируется **машинное обучение**: агент (ML-Agents) получает ровно те же органы управления, что и игрок, и должен сам научиться делать трюки, например тейлвип, не имея заготовленных анимаций. Это одновременно проверка того, что трюки действительно «получаются» из физики, и основа для NPC-райдеров.

Также в идеях: разбор полёта в повторе (центр масс, моменты, силы контакта), тактильная отдача через вибрацию геймпада, редактор спотов, трюки второй волны (фингервип, киклес, ДС, бартвист, брай).
